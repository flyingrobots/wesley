# E4 — Privacy Type Schemas: Task Specs

> Schema-defined privacy types that participate in hashing and CAS storage.

---

## E4.1 — Privacy Type Canonical Encodings

**User Story**

As the Echo privacy layer, I need Wesley-generated canonical encoders for `ClaimRecord`, `PrivateAtomRefV1`, and `OpaqueRefV1` so that privacy-sensitive data participates in the same content-addressed storage system as public data, with identical determinism guarantees.

**Requirements**

Per SPEC-0008 Wave 5:

- `ClaimRecord` encoding must include: `claim_key`, `scheme_id`, `statement_hash`, `commitment`, `proof_bytes` or `proof_hash`, `private_ref`, `policy_hash`, `issuer`
- `PrivateAtomRefV1` encoding must include: `commit`, `policy_hash`, `statement_hash`, `zk_evidence`, `opaque_ref`
- `OpaqueRefV1` encoding must include: `vault_id`, `locator`, `commit`, `alg_id`, `policy_hash`
- All three types must use `raw_le` encoding (same as E2a)
- All three types must have golden vectors (Rust + TypeScript)
- Privacy types may contain variable-length binary fields (`proof_bytes`, `zk_evidence`) — these use the same length-prefixed encoding as `String` but without UTF-8 validation
- `policy_hash` fields are `[u8; 32]` (fixed-size, encoded as 32 raw bytes — no length prefix)

**Acceptance Criteria**

- [ ] All 3 privacy types have `raw_le` encoders generated by Wesley
- [ ] Golden vectors pass in both Rust and TypeScript
- [ ] `policy_hash` is encoded as exactly 32 bytes (no length prefix)
- [ ] Variable-length binary fields use length-prefixed encoding
- [ ] Round-trip: `decode(encode(value)) == value` for all valid inputs

**Scope / Out of Scope**

| In scope | Out of scope |
| --- | --- |
| Canonical encoding for 3 privacy types | ZK proof generation or verification |
| Golden vectors | Vault storage implementation (Echo-side) |
| Binary field encoding | Encryption |
| Fixed-size hash field encoding | Key management |

**Expected Complexity**

~200–300 LoC (schema definitions already done in E2b.1; this is encoder generation + vectors)

**Est. Human Working Hours:** 6–10h

**Test Plan**

- **Golden path:** Encode a `ClaimRecord` with known field values, assert hex matches golden vector. Decode, assert round-trip.
- **Failure modes:** Truncated `proof_bytes` during decode → `DecodeError`. `policy_hash` field with wrong length → `DecodeError`.
- **Edges:** `proof_bytes` of zero length (valid — empty proof). `zk_evidence` of maximum length (e.g., 1MB). `ClaimRecord` with all optional fields set to `None`. `OpaqueRefV1` with empty `locator`.
- **Fuzz/stress:** Property-based test: 5,000 random `ClaimRecord` instances, assert round-trip. Fuzz decoder with random bytes, assert no panics.

**Definition of Done**

- [ ] All 3 privacy types have working `raw_le` encoders in Rust and TypeScript
- [ ] At least 10 golden vectors per type (30 total)
- [ ] Round-trip property tests pass
- [ ] Decoder fuzz test runs for 60 seconds with no panics
- [ ] Privacy types integrate with Echo's `BlobStore` (coordinated Echo PR)

**Blocking:** nothing currently
