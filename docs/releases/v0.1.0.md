# Wesley v0.1.0

## Summary

Wesley `0.1.0` is the LE-binary codec-plan release. It moves Rust and
TypeScript LE-binary codec emission onto a shared, language-neutral plan and
uses that shared shape to ship the breaking TypeScript decode result contract.

This is a pre-1.0 minor release because generated TypeScript decode functions
now return `Result<T>` instead of raw decoded values.

## What Changed

- Added `wesley-emit-codec`, which lowers Wesley L1 IR and selected operations
  into shared `CodecDef` and `CodecOp` data.
- Re-pointed Rust and TypeScript LE-binary emitters at the shared codec plan.
- Preserved byte-identical TypeScript output during the pure refactor slice
  before the intentional decode contract change.
- Changed TypeScript public `decode*` wrappers to return `Result<T>`.
- Added a single TypeScript decode boundary that catches thrown codec/runtime
  failures and converts them to `err`.
- Added TypeScript trailing-byte rejection after top-level decode, matching the
  Rust #603 guard.
- Emitted `Writer`, `Reader`, and `CodecError` runtime port definitions at the
  generated codec boundary.
- Regenerated Rust and TypeScript LE-binary codec golden fixtures.
- Bumped publishable Rust crates and internal crate dependencies to `0.1.0`.

## Why It Matters

The Rust and TypeScript LE-binary emitters used to duplicate codec lowering
logic in each generator. That made drift likely: a fix in one language could
silently miss the other language.

The shared plan makes the codec shape language-neutral first, then lets each
emitter focus on its own syntax and runtime idioms. The decode result contract
also gives TypeScript callers an explicit success/failure value while keeping
the internal generated helpers straightforward.

## Breaking Changes

TypeScript generated public decode functions now return `Result<T>`:

```ts
type Result<T> = { ok: true; value: T } | { ok: false; error: CodecError };
```

Callers that previously used:

```ts
const value = decodeMakeWidget(reader);
```

must now handle the result:

```ts
const decoded = decodeMakeWidget(reader);
if (!decoded.ok) {
  throw decoded.error;
}
const value = decoded.value;
```

Generated TypeScript decoders also require the runtime `Reader` to expose
`remaining(): number`, and the runtime `CodecError` import must be constructible
by the generated boundary.

## Migration

1. Update generated TypeScript decode call sites to branch on `result.ok`.
2. Ensure the TypeScript runtime `Reader` implementation provides
   `remaining(): number`.
3. Ensure the TypeScript runtime `CodecError` implementation can be constructed
   with a message string.
4. Regenerate downstream LE-binary TypeScript and Rust codec outputs together so
   the shared plan, runtime ports, and goldens stay aligned.

Rust decode call sites already use `Result` and should not need a matching API
migration for this release.
