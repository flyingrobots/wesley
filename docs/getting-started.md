# Getting started

This walkthrough starts in an empty directory and ends with a check you can put
in CI. Every command and every output below is real: the outputs were captured
from version 0.3.0-alpha.2.

## 1. Install

```bash
cargo install wesley-cli --version 0.3.0-alpha.2
wesley doctor
```

`doctor` checks that the CLI, the lowerer, and the emitters are present:

```text
[pass] wesley-cli 0.3.0-alpha.2 (rust-native)
[pass] wesley-core lowerer accepts minimal SDL
[pass] normalized SDL hash evidence is available
[pass] wesley-emit-rust 0.3.0-alpha.2 available
[pass] wesley-emit-typescript 0.3.0-alpha.2 available
```

## 2. Write a schema

Save this as `shop.graphql`:

```graphql
type Product {
  id: ID!
  name: String!
  priceCents: Int!
  tags: [String!]!
}

type Query {
  product(id: ID!): Product
  products: [Product!]!
}
```

## 3. Hash it

```bash
wesley schema hash --schema shop.graphql
```

```text
c876e111112a5efc81126f5f7ac1ace60b033c111a42f2b5bb9b997a4c789ebc
```

The hash is computed from the lowered schema, not from the file's bytes.
Changing whitespace or comments does not change it. Changing a type does, and
so does reordering types or fields: order is part of the lowered schema.

## 4. See what Wesley understood

`schema lower` prints the intermediate representation: what the hash, the diff,
and the emitters work from. The operation listing in the next step is the one
exception: it reads the SDL again, on its own. The IR is JSON, versioned, and
deterministic:

```bash
wesley schema lower --schema shop.graphql --json
```

```json
{
  "version": "1.0.0",
  "types": [
    {
      "name": "Product",
      "kind": "OBJECT",
      "directives": {},
      "fields": [
        {
          "name": "id",
          "type": { "base": "ID", "nullable": false, "isList": false },
          "directives": {}
        }
      ]
    }
  ]
}
```

The listing above is shortened to one field. Directives in your schema are
carried through as data, with their arguments. A small fixed set of names is
rewritten to a canonical spelling on the way: `@table` is recorded as
`wes_table`, for example. [Architecture](architecture.md) lists them.

`schema operations` lists the fields of `Query`, `Mutation`, and `Subscription`
with their arguments and result types:

```bash
wesley schema operations --schema shop.graphql
```

```json
[
  {
    "operationType": "QUERY",
    "rootTypeName": "Query",
    "fieldName": "product",
    "arguments": [
      {
        "name": "id",
        "type": { "base": "ID", "nullable": false, "isList": false },
        "directives": {}
      }
    ],
    "resultType": { "base": "Product", "nullable": true, "isList": false },
    "directives": {}
  }
]
```

This listing is shortened too: the real output also has an entry for
`products`.

## 5. Emit code

```bash
wesley emit rust --schema shop.graphql --out shop.rs
wesley emit typescript --schema shop.graphql --out shop.ts
```

`shop.rs` gets a struct for each type, and a request type, a response alias, and
metadata constants for each operation:

```rust
// @generated by Wesley. Do not edit.

#[derive(Debug, Clone, PartialEq, serde::Serialize, serde::Deserialize)]
pub struct Product {
    pub id: String,
    pub name: String,
    #[serde(rename = "priceCents")]
    pub price_cents: i32,
    pub tags: Vec<String>,
}

#[derive(Debug, Clone, PartialEq, serde::Serialize, serde::Deserialize)]
pub struct QueryProductRequest {
    pub id: String,
}

pub type QueryProductResponse = Option<Product>;

impl QueryProductRequest {
    pub const OPERATION_TYPE: &'static str = "QUERY";
    pub const FIELD_NAME: &'static str = "product";
    pub const DIRECTIVES_JSON: &'static str = "{}";
}
```

`shop.ts` gets the same shapes as interfaces and typed operation descriptors:

```ts
/* @generated by Wesley. Do not edit. */

export interface Product {
  id: string;
  name: string;
  priceCents: number;
  tags: string[];
}

export interface QueryProductRequest {
  id: string;
}

export type QueryProductResponse = Product | null;

export const queryProductOperation = {
  operationType: 'QUERY',
  fieldName: 'product',
  directives: {}
} as const;
```

The generated Rust derives `serde::Serialize` and `serde::Deserialize`, so the
crate that includes the file needs `serde` with its `derive` feature:

```toml
serde = { version = "1", features = ["derive"] }
```

## 6. Catch a breaking change

Copy the schema to `shop-v2.graphql`, remove the `tags` field, and add
`description: String`. Then compare the two:

```bash
wesley schema diff --old shop.graphql --new shop-v2.graphql
```

```text
safe      Field "description" added to Product
BREAKING  Field "tags" removed from Product
```

With `--exit-code` the command exits 1 when the change is breaking, which is
what a CI job needs:

```bash
wesley schema diff --old shop.graphql --new shop-v2.graphql --format summary --exit-code
```

```text
1 breaking, 1 safe
```

The steps above work in an empty directory. This last form does not: it is for a
schema that is already committed in a Git repository, and compares the working
copy with the version at a revision:

```bash
wesley schema diff --schema shop.graphql --against origin/main --exit-code
```
